# 校园综合服务平台完整修复设计

## 目标

在保留现有测试数据的前提下，完成数据库备份、乱码数据清洗、auditor 管理员账号恢复，以及学生端闲置列表布局和消息轮询生命周期修复。

## 修复范围

- 备份 `ai_campus_platform` 数据库。
- 检查真实数据库、表和连接字符集，统一为 `utf8mb4`。
- 定向识别并修复首页、消息、闲置、用户昵称等乱码测试数据。
- 将 `auditor` 账号密码重置为 `admin123`，使用完整 BCrypt 哈希。
- 闲置列表改为自适应网格，并补充容器可收缩约束。
- 根据登录状态统一启动和停止未读消息轮询。
- 构建前后端并执行学生端、管理端和核心接口回归测试。

## 安全策略

- 数据修改前生成带时间戳的 SQL 全量备份。
- 数据清洗使用参数化脚本，避免 PowerShell 对 `$` 和中文字符的展开或错误编码。
- 对无法可靠逆向恢复的测试数据，按业务含义替换为清晰、可展示的中文文本。
- 保留备份作为回滚依据，不删除现有业务表或全量重建数据库。

## 验收标准

- 数据库备份文件存在且大小非零。
- 学生端首页、消息和闲置列表不再出现已识别乱码。
- 闲置列表在正常桌面和窄宽度下均可见商品卡片。
- 登录后未读数轮询启动，退出或登录失效后停止，且不会叠加定时器。
- `admin/admin123` 与 `auditor/admin123` 均可登录管理端。
- 学生端、管理端构建成功，后端测试或打包成功。
- AI 会话、PDF 上传等已修复链路不发生回归。
