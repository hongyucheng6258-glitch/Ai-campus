# 平台质量问题完整修复设计

## 目标

在保留现有业务能力的前提下，消除运行检查中发现的乱码、图片失败、日期格式、包体、模块规范和日志冲突问题，并重建一套适合答辩演示的 UTF-8 数据。

## 范围

- 数据库：备份 `ai_campus_platform`，按 `utf8mb4` 重建表和演示数据。
- 管理端：增强审核图片解析和失败占位，统一日期展示。
- 学生端：缩减 Markdown 高亮依赖，消除签到工具模块类型告警。
- 管理端图表：按需引入 ECharts。
- 两端构建：将 Vite 配置迁移为 ESM，并拆分稳定依赖包。
- 后端：排除 PDFBox 传递引入的 `commons-logging`。
- 验证：后端测试、学生端测试、两端构建、依赖树、服务启动和浏览器回归。

## 数据策略

1. 使用 `mysqldump` 生成带时间戳的完整备份，备份失败则停止重置。
2. 检查数据库、表和连接会话字符集。
3. 执行 `schema.sql` 保证结构为 `utf8mb4`。
4. 执行 `reset_and_testdata.sql` 清除已损坏历史数据并导入干净中文演示数据。
5. 抽样检查用户、活动、公告、闲置和失物字段不存在 `?` 或错误解码字符。
6. 数据重置会清除当前业务记录，但备份文件可用于恢复。

## 前端设计

### 图片

管理端新增独立图片规范化工具，兼容数组、JSON 数组字符串、单 URL 和逗号分隔字符串。审核页使用规范化结果，并在资源加载失败时显示明确占位，不让损坏图片影响审核操作。

### 日期

管理端新增日期工具，兼容 ISO、本地日期和空值，统一输出 `YYYY-MM-DD HH:mm`。用户列表和审核列表均通过该工具展示。

### 性能

- ECharts 仅注册折线图、柱状图、饼图及所需组件和 Canvas 渲染器。
- highlight.js 仅注册 Java、JavaScript、TypeScript、Python、SQL、JSON、XML、CSS、Bash 等常用语言。
- Vite 将 Vue、Element Plus、ECharts、Markdown 高亮拆分成稳定 vendor chunk。
- 不在本轮重构 Element Plus 全量注册，避免样式和全局服务回归风险。

### 模块规范

两端 `vite.config.js` 改为 `vite.config.mjs`；签到工具改为 `signinQr.mjs` 并更新引用。清理管理端历史临时 Vite 配置文件。

## 后端设计

在 PDFBox 依赖中排除 `commons-logging`，由 Spring Boot 的 `spring-jcl` 统一日志桥接。通过依赖树确认冲突消失，并运行 PDF/AI 相关测试。

## 非目标

- 不修改现有启动脚本及本机密钥配置。
- 不在本轮重写整个 UI 或引入新的组件框架。
- 不尝试逆向恢复已经替换成 `????` 的不可逆文本。
- 小程序不做视觉重构，只在 Web 与后端修复完成后做基础接口兼容检查。

## 验收标准

- 数据库备份存在且非空，中文演示数据正常。
- 管理端审核图片正常显示；失效资源显示占位。
- 管理端日期无 `T` 分隔符。
- 学生端测试全部通过，后端测试全部通过。
- 两个前端构建成功，ESM/CJS 与 radio 废弃告警消失。
- 后端依赖树不再包含运行时 `commons-logging`。
- 首页、活动、闲置、失物、AI 对话、用户管理、审核、AI 配置均可访问。
